# src

## Purpose
All firmware C sources. Almost everything is CubeMX / CubeIDE output; the hand-written servo and CAN logic lives only in the `USER CODE` blocks of `main.c`.

## Key Files

| File | Description |
|------|-------------|
| `main.c` | Entry point, `SystemClock_Config` (HSE 8 MHz → PLL → 168 MHz), `MX_*_Init`. Hand-written part: `servo[]` table (index = `motor_id`), volatile `target_x10[]` / `dirty[]`, `angle_to_ccr`, `Servo_Start`, `Servo_Update`, `Can_Set`, and the `HAL_CAN_RxFifo0MsgPendingCallback` override. `MX_ADC1_Init` is generated but the ADC is never started |
| `stm32f4xx_hal_msp.c` | HAL MSP: clocks, pins, alternate functions and NVIC for ADC1, CAN1 (PD0/PD1 AF9, `CAN1_RX0_IRQn` priority 0) and TIM2/3/4. `HAL_TIM_MspPostInit` is where each PWM pin is bound to its timer channel, so it is the ground truth for pin ↔ channel |
| `stm32f4xx_it.c` | Exception and IRQ handlers: `SysTick_Handler` → `HAL_IncTick`, `CAN1_RX0_IRQHandler` → `HAL_CAN_IRQHandler(&hcan1)`; fault handlers spin forever |
| `system_stm32f4xx.c` | ST CMSIS `SystemInit` / `SystemCoreClock`. The framework archive `libFrameworkCMSISDevice.a` also holds `system_stm32f4xx.o` and the startup file; the link currently succeeds with this project copy present |
| `syscalls.c` | CubeIDE newlib stubs (`_getpid`, `_kill`, `_open`, `_close`, ...) |
| `sysmem.c` | `_sbrk` for the newlib heap |

## For AI Agents

### Working In This Directory
- Edit `main.c` only inside `USER CODE BEGIN/END` markers. The other files are regenerated by CubeMX; touch them only when removing or adding a peripheral, and mirror that in `can_test.ioc`.
- `HAL_CAN_RxFifo0MsgPendingCallback` overrides a weak HAL symbol, so its name and signature must match exactly.
- ISR/main contract (from `Stm32servosepc.md` §6):
  - The callback validates and stores only; it never writes CCR.
  - `Servo_Update` clears `dirty[i]` **before** reading `target_x10[i]`, so a frame arriving in between is applied on the next pass instead of being lost.
  - No `HAL_Delay` or other blocking wait in the main loop.
- CCR is the pulse width in µs (timer tick = 1 µs, PSC 83, ARR 19999). HAL enables output-compare preload (`OCxPE`) for PWM channels, so a new CCR takes effect at the next 20 ms update event, not mid-pulse.
- Boot sequence: LD4 (green, PD12) is switched on first as a "clock init passed" marker, then `Servo_Start()` (all 10 channels started at CCR = 0, so servos stay still) then `Can_Set()` (accept-all filter into FIFO0, RX notification, `HAL_CAN_Start`). If `Can_Set` fails, `Error_Handler()` halts before the main loop runs.
- Changing a servo's id, pin or channel: update `servo[]`, its comment, `Stm32servosepc.md` §4, `Stm32pinmap.md` §3 and `can_test.ioc` together.

### Testing Requirements
- Build with `~/.platformio/penv/bin/pio run`.
- Logic checks (clamping, ID/DLC/IDE/RTR rejection, id → channel mapping) can be run on the host by compiling the extracted `USER CODE` blocks against stub HAL types; see the root `AGENTS.md`.

### Common Patterns
- Constants are `#define`s in `USER CODE PD` (`SERVO_COUNT`, `CAN_SERVO_STDID`, `SERVO_MIN_US`, ...); shared types in `PTD`; the module-level state is `static` in `PV`; helper prototypes in `PFP`.
- Hand-written code uses tabs and Korean `//` comments.
